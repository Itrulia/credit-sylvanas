# Repo map

A single package. Planned layout; update this file when it changes.

- `src/routes/`: File-based routes. `__root.tsx` is the shell: head, the TSM credit and the "not affiliated" footer, the palette and dev-only devtools. Loaders fill the Query cache (`ensureQueryData`/`prefetchQuery`); search params are validated with zod.
- Legal pages: `/impressum` and `/privacy` (Swiss FADP notice), linked from the footer on every page and listed in `vite.config.ts` prerender pages with `/` and `/about`. When a third party, analytics event type or log retention changes, update `/privacy` and the About privacy section together.
- `public/og.png` (1200x630 share card, no TSM branding; `discovery.test.ts` checks its size): the site-wide `og:image`. `__root.tsx` sets it with `og:site_name`, `og:type`, `theme-color` and `twitter:card`; `pageHead()` in `src/lib/seo.ts` adds `og:title` and `og:description` per route.
- `public/llms.txt`, `robots.txt`, `sitemap.xml`: static discovery files, served as `text/plain`/XML. `llms.txt` lists region pages and describes the item URL pattern (never individual items, never a data dump); `__root.tsx` declares it with `rel="describedby"`. `src/lib/discovery.test.ts` checks their format and that every linked path is a real route, so update them when a page is added or removed.
- `src/router.tsx`: Router plus a per-request `QueryClient` and `setupRouterSsrQueryIntegration`.
- `src/start.ts`: Global server fn middleware. It logs any thrown error and rethrows a bare `Internal server error` (`hideServerError` in `src/lib/errors.ts`), because thrown values are serialised into the HTML. Redirects, not-founds and the no-data marker pass through.
- `src/routeTree.gen.ts`: Generated by the router plugin. Never edit.
- `src/server/`: Server-only code. `db` wraps the D1 binding, `queries` holds the SQL (every history read clamped to 90 days), `ingest` fetches TSM CSVs, validates the header, archives new files to R2, writes an `imports` row per attempt and batches upserts (it never deletes). `fns` holds the server fns (`createServerFn`, zod input), each with its `queryOptions` factory.
- `src/server.ts` (custom server entry): Exports `{ fetch, scheduled }`. `fetch` adds the security headers to every response (`server/security-headers.ts`; `public/_headers` repeats them for static files, which skip the Worker, and gives `/assets/*` a one-year immutable cache), 301s `www.credit-sylvanas.app` to the apex (`server/www-redirect.ts`), then goes through the edge cache (`server/edge-cache.ts`, which drops query params no route schema knows before render and lookup; keys carry `__v={latest imported import id}`, read at most once a minute per isolate, so a new import misses every old entry); `scheduled` dispatches Cron Triggers to ingest and, after a run that imported a file, purges the zone cache when the `CF_PURGE_TOKEN` secret and `CF_ZONE_ID` var are set (`server/ingest/purge.ts`, failures only logged).
- `src/config/realms.ts`: The one typed realm list (`{ region, slug, name, ruleset }`). It ships empty because Forever realm names are unknown. While a region has no realms, `/$region/realms` is `noindex` and stays out of `sitemap.xml` (`discovery.test.ts` expects it back with the first realm).
- `src/components/ui/`: shadcn components, managed by the CLI.
- `src/components/command-palette/`: Generic Mod+K palette ported from wepublish (fuzzy match, search, grouping, provider, trigger). With an empty query, dynamic groups render before the commands. Site commands, the item search group and the Recent and Favourites groups (`saved-item-groups.tsx`) live in `src/components/search/`. With an empty query Recent leaves out the item page you are on and Favourites shows five not already in Recent; once the visitor types, Favourites lists every favourite that fuzzy-matches.
- Per-viewer local storage, never sent anywhere: `src/lib/last-region.ts` and `src/lib/saved-items.ts` (the last 3 item pages viewed, recorded by the item route, and up to 500 favourites toggled by `components/item/favourite-button.tsx`). Both are `useSyncExternalStore` stores with a server snapshot that is empty, every storage call in try/catch, and zod on read. Once a `saved-items` write throws (full or blocked storage), that list stays in memory for the session, because `getItem` can still return the old value. TanStack DB's localStorage collection was measured at about 85 KB gzip, roughly a quarter of the client JS, for lists of a few entries, so it is not used.
- `src/components/`: App components built from `ui/`.
- `src/lib/`: Isomorphic helpers: `search.ts` (route search schemas), `money.ts`, `format.ts`, `bins.ts`, `median.ts`, `heatmap.ts`, `saved-items.ts`, `icons.ts`, `wowhead.ts`, `errors.ts`, `seo.ts`, `last-region.ts` (the viewer's last region in localStorage, the fallback for pages without one via `useRegion()`), and `analytics/` (typed `track(event, props)` over a closed event union plus `trackPageview(pathname)`, which Umami gets as an explicit url and title; adapters `umami.ts`, used only in production builds with a website id, and `noop.ts`; app code never touches `window.umami`). Pageviews come from `components/pageview-tracker.tsx`, once per pathname, with Umami auto-track off. `components/route-focus.tsx` focuses the new page's h1 after each client navigation to a new path. Nothing here may import from `src/server`.
- `src/i18n/`: the typed English catalog (`m.<area>.<key>()`, one `en/<area>.ts` per area), `LOCALE`, `plural()` and the guard test against inline copy. Isomorphic; never imports `src/server`.
- `src/config/regions.ts`: enabled regions in display order (`eu`, then `us` labelled NA; the code stays `us` because it is TSM's file name and the D1 value) and `DISABLED_REGIONS` (KR, TW), shown greyed out in the nav and on the home page but never routed or ingested. Everything else follows `REGIONS`; `llms.txt` and `sitemap.xml` are kept in step by hand. The D1 schema still accepts `kr` and `tw`.
- Fonts are self-hosted, never Google at runtime: Fontsource packages for Newsreader 600 and Atkinson Hyperlegible Next and Mono (variable), imported in `src/styles.css`; the icon font lives in `public/fonts`.
- `src/styles.css`: Tailwind and the tokens of the one light theme (no dark mode, see CONTEXT). Brand colours: oatmilk `#EDE4D3`, forest `#1D4A35`, tomato `#F2462E`.
- `scripts/`: `seed-local.ts` (`pnpm db:seed`), `seed-synthetic.ts` (`pnpm db:synth`), `guard.ts` (refuses `--remote`, `CI`, a remote D1 binding), `fetch-icon-font.ts` (rebuilds the self-hosted Material Symbols subset in `public/fonts` and `icon-font.manifest.json`; rerun after changing `ICON_NAMES`), plus their tests and `wrangler-config.test.ts`.
- `worker-configuration.d.ts`: generated by `pnpm cf-typegen`, committed, never edited.
- `src/server/test/`: Miniflare test setup (migrations, table reset, seeding, stub fetch).
- `migrations/`: D1 schema as numbered SQL files, applied with `wrangler d1 migrations apply`.
- `wrangler.jsonc`: Worker name, entry, `nodejs_compat`, custom-domain routes (apex and www), the `DB` and `ARCHIVE` bindings, cron triggers and public `vars`.
- `.wrangler/`: Miniflare state, including local D1 and R2. Gitignored.
- `docs/`: `CONTEXT.md` (ground truth) and `DESIGN.md`. Untracked plan files: read them, never commit them.

## The server/client boundary

Route components and `src/lib` reach `src/server` only through a
`createServerFn` call. Never import `#/server/db`, or anything else that pulls
in the D1 binding, from a component, a route's component code or `src/lib`.
Write route-level `server: { handlers }` blocks literally inside the
`createFileRoute` call ([gotchas.md](gotchas.md)). `pnpm build` is the check.

## Where to start

- New price view: `src/routes/...` plus a server fn and its `queryOptions` in `src/server/fns`
- New CSV column or TSM format change: the header schema in `src/server/ingest`, a fixture and a spec
- New table or column: a new file in `migrations/` (never edit an applied one), then the queries in `src/server/db`
- Add a realm: `src/config/realms.ts`
