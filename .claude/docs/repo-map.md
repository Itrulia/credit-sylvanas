# Repo map

A single package. Planned layout; update this file when it changes.

- `src/routes/`: File-based routes. `__root.tsx` is the shell: head, theme, the TSM credit and the "not affiliated" footer, the palette and dev-only devtools. Loaders fill the Query cache (`ensureQueryData`/`prefetchQuery`); search params are validated with zod.
- `src/router.tsx`: Router plus a per-request `QueryClient` and `setupRouterSsrQueryIntegration`.
- `src/routeTree.gen.ts`: Generated by the router plugin. Never edit.
- `src/server/`: Server-only code. `db` wraps the D1 binding, `queries` holds the SQL (every history read clamped to 90 days), `ingest` fetches TSM CSVs, validates the header, archives new files to R2, writes an `imports` row per attempt and batches upserts (it never deletes). `fns` holds the server fns (`createServerFn`, zod input), each with its `queryOptions` factory.
- `src/server.ts` (custom server entry): Exports `{ fetch, scheduled }`; `scheduled` dispatches Cron Triggers to ingest.
- `src/config/realms.ts`: The one typed realm list (`{ region, slug, name, ruleset }`). It ships empty because Forever realm names are unknown.
- `src/components/ui/`: shadcn components, managed by the CLI.
- `src/components/command-palette/`: Generic Mod+K palette ported from wepublish (fuzzy match, search, grouping, provider, trigger). Site commands and the item search group live in `src/components/search/`.
- `src/components/`: App components built from `ui/`.
- `src/lib/`: Isomorphic helpers: `search.ts` (route search schemas), `money.ts`, `format.ts`, `bins.ts`, `median.ts`, `heatmap.ts`, `icons.ts`, `wowhead.ts`, `theme.ts`, `errors.ts`, `seo.ts`. Nothing here may import from `src/server`.
- `src/config/regions.ts`: region codes and names.
- `src/styles.css`: Tailwind and theme tokens. Brand colours: oatmilk `#EDE4D3`, forest `#1D4A35`, tomato `#F2462E`.
- `scripts/`: `seed-local.ts` (`pnpm db:seed`), `seed-synthetic.ts` (`pnpm db:synth`), `guard.ts` (refuses `--remote`, `CI`, a remote D1 binding), plus their tests and `wrangler-config.test.ts`.
- `worker-configuration.d.ts`: generated by `pnpm cf-typegen`, committed, never edited.
- `src/server/test/`: Miniflare test setup (migrations, table reset, seeding, stub fetch).
- `migrations/`: D1 schema as numbered SQL files, applied with `wrangler d1 migrations apply`.
- `wrangler.jsonc`: Worker name, entry, `nodejs_compat`, the `DB` and `ARCHIVE` bindings, cron triggers and public `vars`.
- `.wrangler/`: Miniflare state, including local D1 and R2. Gitignored.
- `docs/`: `CONTEXT.md` (ground truth) and `DESIGN.md`. Untracked plan files: read them, never commit them.

## The server/client boundary

Route components and `src/lib` reach `src/server` only through a
`createServerFn` call. Never import `#/server/db`, or anything else that pulls
in the D1 binding, from a component, a route's component code or `src/lib`.
Write route-level `server: { handlers }` blocks literally inside the
`createFileRoute` call ([gotchas.md](gotchas.md)). `pnpm build` is the check.

## Where to start

- New price view: `src/routes/...` plus a server fn and its `queryOptions` in `src/server/fns`
- New CSV column or TSM format change: the header schema in `src/server/ingest`, a fixture and a spec
- New table or column: a new file in `migrations/` (never edit an applied one), then the queries in `src/server/db`
- Add a realm: `src/config/realms.ts`
