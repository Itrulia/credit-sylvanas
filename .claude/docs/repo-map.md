# Repo map

A single package. Planned layout; update this file when it changes.

- `src/routes/`: File-based routes. `__root.tsx` is the shell: head, the TSM credit and the "not affiliated" footer, the palette and dev-only devtools. Loaders fill the Query cache (`ensureQueryData`/`prefetchQuery`); search params are validated with zod.
- Legal pages: `/impressum` and `/privacy` (Swiss FADP notice), linked from the footer on every page and listed in `vite.config.ts` prerender pages with `/` and `/about`. When a third party, analytics event type or log retention changes, update `/privacy` and the About privacy section together.
- `src/router.tsx`: Router plus a per-request `QueryClient` and `setupRouterSsrQueryIntegration`.
- `src/routeTree.gen.ts`: Generated by the router plugin. Never edit.
- `src/server/`: Server-only code. `db` wraps the D1 binding, `queries` holds the SQL (every history read clamped to 90 days), `ingest` fetches TSM CSVs, validates the header, archives new files to R2, writes an `imports` row per attempt and batches upserts (it never deletes). `fns` holds the server fns (`createServerFn`, zod input), each with its `queryOptions` factory.
- `src/server.ts` (custom server entry): Exports `{ fetch, scheduled }`. `fetch` 301s `www.credit-sylvanas.app` to the apex (`server/www-redirect.ts`), then goes through the edge cache (`server/edge-cache.ts`, keys carry `__v={latest imported import id}`, read at most once a minute per isolate, so a new import misses every old entry); `scheduled` dispatches Cron Triggers to ingest and, after a run that imported a file, purges the zone cache when the `CF_PURGE_TOKEN` secret and `CF_ZONE_ID` var are set (`server/ingest/purge.ts`, failures only logged).
- `src/config/realms.ts`: The one typed realm list (`{ region, slug, name, ruleset }`). It ships empty because Forever realm names are unknown.
- `src/components/ui/`: shadcn components, managed by the CLI.
- `src/components/command-palette/`: Generic Mod+K palette ported from wepublish (fuzzy match, search, grouping, provider, trigger). Site commands and the item search group live in `src/components/search/`.
- `src/components/`: App components built from `ui/`.
- `src/lib/`: Isomorphic helpers: `search.ts` (route search schemas), `money.ts`, `format.ts`, `bins.ts`, `median.ts`, `heatmap.ts`, `icons.ts`, `wowhead.ts`, `errors.ts`, `seo.ts`, and `analytics/` (typed `track(event, props)` over a closed event union plus `trackPageview()`; adapters `umami.ts`, used only in production builds with a website id, and `noop.ts`; app code never touches `window.umami`). Pageviews come from `components/pageview-tracker.tsx`, once per pathname, with Umami auto-track off. Nothing here may import from `src/server`.
- `src/config/regions.ts`: region codes and names.
- Fonts are self-hosted, never Google at runtime: Fontsource packages for Newsreader 600 and Atkinson Hyperlegible Next and Mono (variable), imported in `src/styles.css`; the icon font lives in `public/fonts`.
- `src/styles.css`: Tailwind and the tokens of the one light theme (no dark mode, see CONTEXT). Brand colours: oatmilk `#EDE4D3`, forest `#1D4A35`, tomato `#F2462E`.
- `scripts/`: `seed-local.ts` (`pnpm db:seed`), `seed-synthetic.ts` (`pnpm db:synth`), `guard.ts` (refuses `--remote`, `CI`, a remote D1 binding), `fetch-icon-font.ts` (rebuilds the self-hosted Material Symbols subset in `public/fonts` and `icon-font.manifest.json`; rerun after changing `ICON_NAMES`), plus their tests and `wrangler-config.test.ts`.
- `worker-configuration.d.ts`: generated by `pnpm cf-typegen`, committed, never edited.
- `src/server/test/`: Miniflare test setup (migrations, table reset, seeding, stub fetch).
- `migrations/`: D1 schema as numbered SQL files, applied with `wrangler d1 migrations apply`.
- `wrangler.jsonc`: Worker name, entry, `nodejs_compat`, custom-domain routes (apex and www), the `DB` and `ARCHIVE` bindings, cron triggers and public `vars`.
- `.wrangler/`: Miniflare state, including local D1 and R2. Gitignored.
- `docs/`: `CONTEXT.md` (ground truth) and `DESIGN.md`. Untracked plan files: read them, never commit them.

## The server/client boundary

Route components and `src/lib` reach `src/server` only through a
`createServerFn` call. Never import `#/server/db`, or anything else that pulls
in the D1 binding, from a component, a route's component code or `src/lib`.
Write route-level `server: { handlers }` blocks literally inside the
`createFileRoute` call ([gotchas.md](gotchas.md)). `pnpm build` is the check.

## Where to start

- New price view: `src/routes/...` plus a server fn and its `queryOptions` in `src/server/fns`
- New CSV column or TSM format change: the header schema in `src/server/ingest`, a fixture and a spec
- New table or column: a new file in `migrations/` (never edit an applied one), then the queries in `src/server/db`
- Add a realm: `src/config/realms.ts`
